06 / ELECTRICAL ENGINEERING MODEL

CE Voltage Divider Reference: อะไรคือ Input และ Output จริง?

DC Operating Point (.op)ใช้ VCC, R1, R2, RC, RE และ BJT model จากวงจรเดิม โดย Coupling Capacitors เปิดวงจรเมื่อวิเคราะห์ DC; อ่าน VB, VE, VC, VCE, IC ตามทิศอ้างอิงที่นิยามไว้
AC Small-signal (.ac)ใช้ AC excitation และวงจร Cin/Cout/RL แสดงอัตราขยายเชิงขนาด |Vout/Vin| และเฟสตามความถี่ ระบุว่าจุดวัด Vin คือจุดใด เพื่อไม่ให้คำนวณ Gain จากคนละตำแหน่ง
Transient (.tran)ใช้แหล่งสัญญาณ SIN ที่ตั้ง Amplitude และ Frequency วัด Vin/Vout กับเวลา; ตรวจการกลับเฟสและการเปลี่ยนตามอินพุต
Analytical Referenceผลเดิมจาก dc_bias.py เป็นการประมาณด้วย β และ VBE คงที่; ผลจาก ngspice เป็นอีกชุดหนึ่งที่ขึ้นกับ BJT model และสภาวะ ไม่บังคับให้ตัวเลขเท่ากันทุกหลัก
Baseline Referenceค่าตั้งต้นสำหรับการสาธิตใช้เพื่ออะไร
VCC / R1 / R212 V / 100 kΩ / 22 kΩDC bias จาก Lab 2–3
RC / RE / RL2.2 kΩ / 1 kΩ / 10 kΩโหลดตัวขยาย
Cin / Cout10 µF / 10 µFInput/Output coupling
Source10 mV peak / 1 kHzTransient input; เปลี่ยนค่าเพื่อดูพฤติกรรม
BJT Modelใช้ Model ที่ Instructor Starter Kit ระบุชื่อและพารามิเตอร์ให้รันซ้ำได้; ไม่เดาค่าเฉพาะรุ่น
ตัวเลขเหล่านี้เป็น Input Fixture ไม่ใช่ผลคำนวณ/กราฟที่ยืนยันแล้ว ห้ามใส่ตัวเลข Gain, fL, fH หรือ Waveform สำเร็จรูปโดยอ้างว่าเป็นผล ngspice ก่อนรันจริง และห้ามเปรียบเทียบกับผล Analytical โดยไม่กล่าวถึงสมมติฐานของแต่ละโมเดล

สามารถใช้ Emitter Bypass Capacitor เป็นงานเพิ่มเติมได้ภายหลัง แต่ Baseline ไม่ต้องมี CE เพื่อไม่เพิ่มสาขาการวิเคราะห์หลายรูปแบบในเวลาเดียวกัน

3 โหมดการวิเคราะห์ต้องแตกต่างกันจริง

Modeคำสั่งวิเคราะห์ ngspiceข้อมูลที่ต้องแสดง
DC.opOperating point และสถานะวงจร
AC.acFrequency, Gain Magnitude/Phase (กำหนด reference ชัด)
Transient.tranTime, Vin, Vout, amplitude และการกลับเฟส

หมายเหตุ: การหาค่า Cutoff Frequency ต้องมีจุดอ้างอิง -3 dB และช่วง sweep ที่ครอบคลุมพอ หากกราฟไม่มีจุดตัด ให้ระบุ “not determined in sweep range” แทนการสร้างตัวเลขขึ้นเอง

หลักการเขียนโปรแกรมที่ต้องอธิบายให้ได้

  1. External Process: Python เรียกโปรแกรมอื่นอย่างไร? ให้ AI แสดงโค้ด subprocess.run ที่รับ Argument เป็น List, ไม่ใช้ shell=True, กำหนด timeout และแยก Working Directory สำหรับแต่ละรอบ
  2. Input Validation: ตรวจความเป็นตัวเลข หน่วย ช่วงบวก และข้อจำกัดด้านเวลา/ความถี่ก่อนสร้าง Netlist; ไม่ให้ข้อความจากฟอร์มเข้า Command/Solver โดยไม่ตรวจ
  3. Result Parsing: บอกได้ว่าข้อมูลจาก ngspice อยู่ในไฟล์หรือ Log ใด และถูกแปลงเป็น Array/List ของตัวเลขพร้อมหน่วยอย่างไร
  4. Separation of Concerns: app.py รับคำสั่ง, Engine Adapter ดูแล Solver, dc_bias.py เป็น Reference; Browser แสดงผลที่ได้รับ ไม่คำนวณแกนฟิสิกส์ใหม่
  5. Error Handling: Solver ไม่พบ, Run Failed, Output ว่าง, Timeout หรือ Input ผิด ต้องไม่คืนกราฟเก่าพร้อมสถานะ Success
แนวทาง Batch Run ที่ควรรู้: การใช้ ngspice แบบ Batch สามารถรัน Netlist ที่มี Analysis Directive และบันทึก Output ได้ เช่น ngspice -b -o run.log -r run.raw circuit.cir โดยให้ Starter Kit กำหนดการสร้าง Netlist/อ่านไฟล์แต่ละ Analysis ให้ถูกต้อง ไม่ผสม .control ... .endc กับวิธี Batch นี้โดยไม่ตรวจเอกสาร/ทดสอบก่อน

หากใช้ Chart Library ให้เพิ่มเฉพาะเมื่อจำเป็นและบันทึก Dependency จริงใน README; กราฟที่เป็น SVG/Canvas/รูปที่ฝังใน HTML ใช้ได้ ตราบใดที่ได้ข้อมูลจากการรัน ngspice และ Browser แสดงจริง
